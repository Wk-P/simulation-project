## 用户登录的要求
- 用户不需要注册，管理员统一创建

第一版
- username + password

role
- ADMIN / OPERATOR
    - ADMIN：创建、禁用运维账户
    - OPERATOR：登记、修改、停止监控HTTP服务，可以手动检查、查看检查记录
- ADMIN 也拥有所有OPERATOR权限
### 额外要求
- 被禁用的用户不可以再登录
- 用户可以修改密码
- 管理员可以重置用户密码，但是管理员不能重置自己的密码。被重置密码的用户丧失全部会话，需要重新登录。管理员界面显示重置的一次性临时新密码，通过其他渠道告诉用户；用户拿到新密码后，强制修改密码才能使用系统功能。
- 用户登录后不应该每次操作都重新输入密码
- 有一键全设备踢下线功能。

### 登录生命周期
- 最长登录8小时，8小时候必须重新登录
- 30分钟无操作自动重新登录。

- 管理员禁用该账号；
- 管理员重置该用户密码。

暂时不因为管理员权限更高而设置不同的登录时长

管理员确认行为：
- 重置密码
- 禁用用户
以上两种行为都需要管理员再次输入密码

## HTTP service 权限问题
- 虽然是health 但是是否需要鉴权

回复：MVP需要支持两种方式
- 不需要鉴权的
- 需要凭证的：凭证由运维人员在登记或修改 Service 时配置。普通 OPERATOR 可以配置，因为他们本来就负责 Service 管理。
```text
可以提示，但系统必须能够可靠判断凭证确实过期。
如果目标 health endpoint 明确返回“凭证已过期”的信息，我们希望界面显示类似：
Credential expired

如果只能知道鉴权失败，无法区分“过期、错误、被撤销、权限不足”，那就只显示：
Authentication failed

不要把无法确定的鉴权失败直接描述成“凭证过期”。
MVP 不要求主动在凭证即将过期前提醒运维，也不要求系统解析所有类型凭证的有效期。
```
