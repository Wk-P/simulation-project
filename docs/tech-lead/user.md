# 用户系统的架构实现
## 注册
### 流程
输入 -> 校验 -> 创建 -> 持久化 -> 输出



### 已知需求
提交 username 和 password，系统创建账号


#### 输入
- username / password
#### 检查合法性

##### 检查-1
- username / password 不能是空字符串
- username 不能是纯数字
- password 安全性要求
- username 长度限制
- password 最短长度
- 允许字符集

- 一旦输入不合法，直接终止注册流程

##### 检查-2
- 检查用户名是否重复
    - 查到重复，注册失败
    - 不重复，进行下一步


#### 密码加密
- 使用hash加密密码

#### 数据保存
- 创建数据对象
- 写入数据库
- 数据表新增记录


#### 返回信息
这一步返回执行结果
- 如果数据库没问题，返回201状态码
- 其他就对应返回状态码
    - 500 - 服务器问题
    - 401 - 用户名已经存在
    - 400 - 输入不合法


## 转移到 FastAPI 框架
### FastAPI Router
- 接收 POST /register 请求
- 读取 username / password
- 调用注册业务逻辑
- 把业务结果转换成 HTTP response

### 业务逻辑
- 校验输入信息
- 判断注册流程应该如何执行
- 密码 hash
- 创建 User 对象
- 决定何时查询、何时保存

### 数据库访问
- 查询 username 是否存在
- 写入 User
